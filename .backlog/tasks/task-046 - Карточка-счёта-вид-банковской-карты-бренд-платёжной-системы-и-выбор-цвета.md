## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Карточка счёта (TASK-006) пока не похожа на банковскую карту из референса Moni (docs/design/reference/moni/12.webp). Данных для этого хватает: баланс, валюта, тип счёта, реквизиты. Нужно сделать карточку узнаваемо картой: с блеском и преломлением света на поверхности, как в Moni, и дать пользователю выбирать цвет счёта в его настройках, листая варианты прямо на карточке.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Карточка выглядит как банковская: баланс, последние цифры (••2340), срок или другой реквизит, чип, слот для бренда, как в референсе Moni
- [ ] #2 Для карты показывается бренд Visa или Mastercard; для обычного счёта вместо карточных реквизитов номер счёта; для крипты значок криптовалюты, кошелька или биржи
- [ ] #3 На поверхности карточки есть эффект преломления света, как в референсе, одинаково хорошо смотрится в светлой и тёмной теме
- [ ] #4 В настройках счёта есть выбор цвета: несколько готовых вариантов, переключаются свайпом по карточке, превью меняется сразу
- [ ] #5 Выбранный цвет сохраняется в счёте (миграция, контракт API, RLS не нарушен), работает офлайн и отражается везде, где показывается карточка: стопка на экране Счетов, экран счёта, главная
- [ ] #6 У счетов без выбранного цвета остаётся осмысленный цвет по умолчанию, текст на любом цвете проходит проверку контраста
- [ ] #7 Реквизиты и номера не попадают в логи; полные номера карт не хранятся и не показываются
- [ ] #8 Анимация свайпа уважает prefers-reduced-motion; тесты покрывают выбор бренда и выбор цвета
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Данные. ACCOUNT_COLORWAYS в packages/domain (hue-only набор), colorway в AccountDtoSchema и accountFields (contracts), миграция accounts.colorway text null + check по списку (RLS уже на таблице), проброс в AccountRow/toColumns/SELECT pg-репозитория, memory-репозиторий и dto.ts API.
2. Токены и заливка. ACCOUNT_COLORWAY_HUES рядом с currency-tint.ts; cardTintStyle(code, colorway) — colorway задаёт только --mm-card-hue, светлота и цветность остаются темой, поэтому гарантия контраста из tokens-contrast.test.ts действует без изменений. Пустой colorway = оттенок валюты (AC#6).
3. Блеск. Утилита card-gloss в packages/ui/src/styles/index.css: слоистые градиенты поверх заливки, своя непрозрачность в светлой и тёмной теме, ничего не рисует под prefers-reduced-motion только если появится движение (сам блеск статичен).
4. Карта как банковская. AccountCard.vue: чип, слот бренда, маскированные цифры (••2340), срок; для kind=card — Visa/Mastercard из cardNetwork через новый CardBrandMark.vue + нормализатор card-brand.ts; для обычного счёта вместо реквизитов — номер счёта/название; для крипты — значок валюты. Полные номера не хранятся и не показываются, в логи ничего не пишется (AC#7).
5. Выбор цвета. AccountColorway swipe: композабл жеста (переиспользовать подход use-drag-reorder), превью карточки в форме счёта меняется сразу, есть клавиатурная альтернатива и точки-индикаторы; свайп уважает prefers-reduced-motion (AC#8).
6. Проброс во все места карточки. application/account-cards.ts — единая чистая сборка AccountCardItem из AccountDto (цвет, бренд, реквизиты), используется экраном Счетов, экраном счёта и полосой на главной; домен Account не трогаем.
7. Офлайн и сохранение. colorway идёт обычным PATCH через useUpdateAccount с оптимистичным патчем; проверить, что отложенная запись восстанавливается (AC#5).
8. Локали ru/en, тесты: выбор бренда, выбор цвета, дефолтный цвет, контраст, reduced-motion. bun run test/lint/typecheck.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Данные: colorway (text, nullable, check по списку из packages/domain) в accounts — миграция 20260920000018. Пусто = цвет валюты, как было до выбора; поле не привязано к kind, потому что карточку рисуем для любого счёта. Применено локально (supabase db reset), проверено: неизвестный цвет отклоняется, известный принимается, счёт без цвета проходит; RLS на таблице не трогали.

Палитра: hue-only (решение пользователя). ACCOUNT_COLORWAY_HUES задаёт только --mm-card-hue, светлота и цветность остаются темой — значит гарантия контраста из tokens-contrast.test.ts продолжает действовать, и карточка перекрашивается вместе с темой.

Найденный дефект: блеск (card-gloss) кладётся поверх заливки, а старый 360-градусный тест мерил голый тинт. В тёмной теме самый светлый угол карточки давал ink 3.7:1 — ниже AA. Значения тёмного блеска снижены (sweep 0.05, bloom 0.06, shade 0.2), и добавлен тест 'the card tint under its sheen', который композитит блеск на тинт и обходит все 360 оттенков в обеих темах. Проверено, что тест краснеет на старых значениях.

Свайп: pointer events, порог 48px, композитинг только через transform. Точки — radiogroup с roving tabindex и стрелками (были toggle-кнопки с aria-pressed: для выбора одного из семи это неверно озвучивается).

Реквизиты обычного счёта — банк и страна, а не номер: номера счетов не храним (согласовано с пользователем). Полный номер карты не хранится и не показывается — только 4 цифры.

Офлайн: PATCH счёта переведён на зарегистрированный ключ мутации UPDATE_ACCOUNT_KEY с оптимистичным патчем, как recordBalance. Теперь правка (в том числе цвет и звезда) переживает закрытую вкладку и уходит сама при связи.

Визуальная проверка: временный vite-стенд с реальными компонентами и стилями, светлая и тёмная тема, скриншоты. По ним исправлено: пустота в середине карточки (min-h-44 -> min-h-36), чип читался как иконка таблицы (перерисован заливкой со швами), на узкой карточке полосы номер обрезался до '•• 23…' (срок на sm убран). Свайп проверен настоящим drag'ом в браузере: карточка перекрасилась, активная точка сместилась.

Проверки: bun run test (1010 тестов), typecheck, lint, build — всё зелёное.
