## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
На внутренних экранах в шапке нет привычной навигации назад, а сама шапка сложнее, чем в референсе Moni. В дизайне Moni шапка простая: слева кнопка навигации (назад), справа кнопка действия экрана. Нужно привести шапку приложения к этой схеме в рамках текущего дизайна.

Правая кнопка — контекстная: её смысл задаёт открытый экран, а не сама шапка. На форме редактирования счёта это «Сохранить» (сабмит формы прямо из шапки), на списке — «Добавить», на экране без действия место пустое. То есть нужен сквозной UX-флоу: экран объявляет своё действие (подпись, обработчик, состояния disabled/loading), шапка его показывает; при этом форма остаётся сабмитабельной и со своей страницы.

Переключатель темы из шапки убираем: селектор темы уже живёт в настройках (apps/web/src/modules/profile/ui/SettingsPage.vue), пусть остаётся только там.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. shared/layout/page-action.ts: контракт PageAction (label, onSelect, disabled, pending, icon, testid) + providePageAction() в оболочке и usePageAction() на экране (provide/inject, самоочистка при уходе экрана).

7. Тесты: показ и скрытие «назад» (корень таба против вложенного экрана), пустое место без действия, отрисовка и клик действия, отсутствие переключателя темы в шапке, действие формы счёта (сабмит, disabled, loading).

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Решения, согласованные с пользователем до реализации: на широких окнах вордмарк и ссылки разделов остаются в центре шапки (нижняя пилюля по-прежнему md:hidden, иначе десктопная навигация теряется); переключатель отображаемой валюты остаётся в шапке слева от кнопки действия.

Контракт: apps/web/src/shared/layout/page-action.ts. Оболочка открывает угол один раз (providePageAction), экран занимает его через usePageAction; очистка при размонтировании сравнивает то, что лежит в слоте, с тем, что положил экран, — Vue монтирует приходящий экран до размонтирования уходящего, и безусловная очистка стирала бы действие нового экрана.

Экраны с действием: форма счёта («Создать»/«Сохранить», disabled пока не заполнены название, банк и страна, спиннер при сохранении), список счетов («Добавить счёт»), План («Добавить …» по открытой вкладке — переехало из заголовка экрана). Остальные экраны действия не объявляют, угол пустой.

Побочно: ключ theme.label («Сменить тему (сейчас {theme})») остался без пользователя после удаления тогла и удалён из ru/en; комментарий к THEMES про тогл оболочки поправлен. Тест смены темы переехал из shell.test.ts в SettingsPage.test.ts — иначе AC#9 остался бы без покрытия. В AGENTS.md записано правило контракта шапки и то, что тест такого действия обязан монтировать экран внутри AppShell.

Проверка: bun run lint, bun run typecheck, bun run test (812 тестов, из них 264 в web), bun run build — всё зелёное. Живая проверка в Chrome на запущенном dev-сервере: /accounts и /plan (корень таба — вордмарк, «назад» нет), /accounts/new и /settings/rates («назад» есть; на курсах угол пуст, так как экран действия не объявляет), кнопка «Создать» неактивна на незаполненной форме и включается по мере заполнения. AC#4 проверен отдельно: «назад» 44x44, aria-label «Назад», видимое кольцо фокуса, светлая и тёмная темы.

Доработка по замечаниям (коммит b8cdd8b):
1. Кнопка действия — ghost, прозрачная, просто слово акцентным цветом в духе iOS. Иконка убрана из контракта PageAction совсем, чтобы экран не мог вернуть диск с глифом; вместо неё появился ariaLabel — короткое «Добавить» видно, а экранной читалке достаётся целая фраза («Добавить счёт», «Добавить источник дохода»). Неактивная кнопка уходит в приглушённый цвет, при сохранении на месте слова крутится спиннер.
2. На главной шапке нечего держать: назад нет, действия нет, переключатель валюты у самого экрана. На телефоне шапка там больше не рисуется (hidden md:block), на широком окне остаётся — в ней живут ссылки разделов.

Попутно найден дефект: Vue приводит отсутствующий Boolean-проп к false, а не к undefined, поэтому выражение showCurrency ?? true в оболочке не срабатывало ни разу и любой потребитель без пропа терял переключатель валюты. Значение по умолчанию переехало туда, где проп объявлен.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Шапка приведена к схеме «навигация слева, действие справа»: слева кнопка «назад» на вложенных экранах (на корневых экранах таба её место занимает вордмарк), справа — единственное действие, которое объявляет сам экран через новый контракт usePageAction/providePageAction в shared/layout; шапка своих действий не придумывает, и без объявленного действия угол пуст. Кнопка «Добавить» на Плане переехала из заголовка экрана в шапку, список счетов получил такую же. Проверено: lint, typecheck, 812 тестов и build зелёные; поведение просмотрено вживую в Chrome на dev-сервере в светлой и тёмной теме, включая размер области нажатия и кольцо фокуса.
