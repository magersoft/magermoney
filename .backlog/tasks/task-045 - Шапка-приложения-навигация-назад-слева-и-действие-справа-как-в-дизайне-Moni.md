## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
На внутренних экранах в шапке нет привычной навигации назад, а сама шапка сложнее, чем в референсе Moni. В дизайне Moni шапка простая: слева кнопка навигации (назад), справа кнопка действия экрана. Нужно привести шапку приложения к этой схеме в рамках текущего дизайна.

Правая кнопка — контекстная: её смысл задаёт открытый экран, а не сама шапка. На форме редактирования счёта это «Сохранить» (сабмит формы прямо из шапки), на списке — «Добавить», на экране без действия место пустое. То есть нужен сквозной UX-флоу: экран объявляет своё действие (подпись, обработчик, состояния disabled/loading), шапка его показывает; при этом форма остаётся сабмитабельной и со своей страницы.

Переключатель темы из шапки убираем: селектор темы уже живёт в настройках (apps/web/src/modules/profile/ui/SettingsPage.vue), пусть остаётся только там.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [x] #1 Слева в шапке кнопка «назад» на экранах, куда заходят из другого экрана; на корневых экранах таба её нет
- [x] #2 Справа в шапке кнопка действия, которое зависит от экрана; если действия нет, место пустое
- [x] #3 Шапка упрощена до схемы «навигация слева, действие справа» по референсу Moni, без лишних элементов
- [x] #4 Кнопки шапки доступны с клавиатуры и экранных читалок (подписи, размер области нажатия), корректно работают в светлой и тёмной теме
- [x] #5 Все существующие экраны переведены на новую шапку, действия, которые раньше жили в шапке, не потеряны
- [x] #6 Тесты покрывают показ и скрытие кнопки «назад» и слот действия
- [x] #7 Экран задаёт действие для правой кнопки шапки: подпись, обработчик и состояния disabled/loading; шапка сама действий не придумывает
- [x] #8 На экране редактирования/создания счёта правая кнопка — «Сохранить», она сабмитит форму и отражает её состояние (неактивна при невалидной форме, показывает загрузку при сохранении)
- [x] #9 Переключатель темы убран из шапки; смена темы остаётся только на экране настроек и продолжает работать

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. shared/layout/page-action.ts: контракт PageAction (label, onSelect, disabled, pending, icon, testid) + providePageAction() в оболочке и usePageAction() на экране (provide/inject, самоочистка при уходе экрана).
2. shared/layout/nav.ts: isRoot(path) — корневой экран таба; backTarget(path) — куда вести «назад», если истории нет.
3. shared/layout/AppHeader.vue: слева «назад» (или вордмарк на корне), в центре вордмарк и ссылки разделов на md+, справа слот валюты и кнопка действия. Переключатель темы удалён.
4. AppShell.vue переходит на AppHeader и раздаёт слот действия; App.vue продолжает вызывать useTheme() ради применения темы, но больше не передаёт её в оболочку.
5. Экраны объявляют действие: AccountFormPage — «Сохранить»/«Создать» (сабмит формы, disabled при невалидной, loading при сохранении, форма остаётся сабмитабельной со своей страницы), AccountsPage — «Новый счёт», PlanPage — «Добавить» вместо своей кнопки в заголовке.
6. i18n: a11y.back в ru/en.
7. Тесты: показ и скрытие «назад» (корень таба против вложенного экрана), пустое место без действия, отрисовка и клик действия, отсутствие переключателя темы в шапке, действие формы счёта (сабмит, disabled, loading).
