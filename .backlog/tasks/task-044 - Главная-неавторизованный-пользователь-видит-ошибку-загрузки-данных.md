## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

Если открыть главную без авторизации, вместо перехода на вход или понятного состояния показывается «ошибка загрузки данных». Запросы дашборда уходят без сессии и падают, а пользователь не понимает, что нужно войти.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->

1. Причина (подтверждена репро-тестом): в app/main.ts router.beforeEach(authGuard) вызывается после app.use(router). Установка роутера уже запустила первую навигацию, а vue-router собирает beforeEach-гарды в микрозадаче внутри неё — гард, добавленный позже (после await init()), первую навигацию не видит. На холодном старте / рендерится Home без сессии, её запросы падают 401 и экран показывает «ошибка загрузки данных».
2. session-store.init() больше не отклоняется: ошибка чтения сохранённой сессии логируется внутри, пользователь считается неавторизованным. Session получает whenReady().
3. authGuard становится асинхронным и ждёт whenReady() перед решением — иначе гард, поставленный до установки роутера, отправлял бы на вход и авторизованного.
4. Новый app/start-routing.ts: регистрирует гард, затем ставит роутер, возвращает router.isReady(). Порядок становится одним именованным тестируемым узлом.
5. main.ts использует его и монтирует приложение только когда маршрут определён.
6. Тесты: гард ждёт позднюю сессию; start-routing уводит анонимную первую навигацию на /sign-in с ?redirect, авторизованную оставляет на /, публичные маршруты пропускает; ошибка загрузки и успех на Home уже покрыты — дополнить проверкой кнопки повтора.

<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->

Причина: app/main.ts регистрировал router.beforeEach(authGuard) после app.use(router) и после await init(). Установка роутера запускает первую навигацию, гарды beforeEach собираются внутри неё — поздний гард первую навигацию не видел. Все последующие навигации были защищены, дыра была ровно в той, с которой человек приходит: холодный старт / рендерил Home без сессии, её запросы падали, экран показывал ошибку загрузки.

Изменения:

- app/start-routing.ts (новый): ставит гард, затем роутер, возвращает router.isReady(). Порядок стал именованным узлом, который покрыт тестом.
- auth/application/auth-guard.ts: гард асинхронный, ждёт session.whenReady() перед решением (иначе, стоя до установки роутера, он уводил бы на вход и авторизованного).
- auth/application/use-session.ts: Session получил whenReady().
- auth/infrastructure/session-store.ts: init() больше не отклоняется — ошибка чтения сохранённой сессии логируется внутри, человек считается неавторизованным (зависшая навигация хуже, чем экран входа).
- app/main.ts: использует startRouting, монтирует приложение когда маршрут определён.

Проверка: bun run test (282 теста web, 63 файла), typecheck, lint, build — всё зелёное. Тест start-routing проверен мутацией: с прежним порядком (гард через макрозадачу после app.use) он падает. В браузере на dev-сервере анонимный заход на / приводит на /sign-in?redirect=/, в сетевом логе ни одного запроса данных главной.

Замечено вне рамок задачи: композиционный корень (App.vue → useDisplayCurrency → useProfile) отправляет GET /me и без сессии — единственный запрос, уходящий на экране входа. Пользователю не виден, данных главной не касается.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->

Гард авторизации регистрировался после установки роутера, поэтому не видел первую навигацию: холодный заход на / рендерил главную без сессии, её запросы падали и экран показывал «ошибка загрузки данных». Порядок вынесен в app/start-routing.ts (гард → роутер → router.isReady()), гард стал асинхронным и сам ждёт чтения сохранённой сессии, а session-store.init() больше не отклоняется. Проверено: 282 теста web зелёные, typecheck/lint/build чистые, тест start-routing падает при возврате прежнего порядка, а в браузере анонимный заход на / приводит на /sign-in?redirect=/ без единого запроса данных главной.
