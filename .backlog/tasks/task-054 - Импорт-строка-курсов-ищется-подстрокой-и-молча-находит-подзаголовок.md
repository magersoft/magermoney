## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Маппер курсов (apps/api/scripts/import/rates-mapper.ts) ищет строки курсов так: rows.find((r) => label.test(r[0])), где label — /USD\/RUB/i и /EUR\/USD/i. Это поиск подстроки по первой ячейке, а не по метке целиком.

В настоящей выгрузке первая строка после заголовка — подзаголовок листа: «Доход помесячно с 2015 г. • USD/RUB — твои годовые курсы EUR/USD — годовые средние (IRS / macrotrends)». В ней есть обе подписи, и она идёт раньше настоящих строк «Курс USD/RUB» и «Курс EUR/USD», поэтому find берёт её. Остальные её ячейки пустые, и на выходе ноль курсов.

Хуже то, что это не падает: mapRates возвращает ok с пустым списком, и импорт печатает «0 rates» — то же самое, что он напечатал бы, если бы курсов в файле действительно не было. База после такого импорта остаётся без курсов, то есть суммы не во что пересчитать, и узнаётся это только на экране.

Воспроизведение: bun run import -- --user <email> --rates imports/rates.csv --dry-run на выгрузке, где есть подзаголовок с упоминанием USD/RUB и EUR/USD. Ожидается 24 курса (12 лет × 2), получается 0.
