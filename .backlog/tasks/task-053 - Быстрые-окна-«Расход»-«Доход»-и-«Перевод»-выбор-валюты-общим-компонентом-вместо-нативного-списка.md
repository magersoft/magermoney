## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Рядом с суммой в быстрых окнах, которые открываются по «+», валюта выбирается нативным выпадающим списком кодов: три буквы без названия, без флага и без поиска. Это единственное оставшееся место в приложении, где валюту выбирают так, — остальные экраны (форма счёта, бюджеты, ручной курс, поступление, экран валют) уже переведены на общий компонент выбора валюты из TASK-050, и человек, привыкший искать «доллар» по названию, здесь этого сделать не может.

Список сидит не в самих окнах, а в общем компоненте быстрого окна дизайн-системы, поэтому «Расход», «Доход» и «Перевод» чинятся одной правкой. Контрол стоит вплотную к сумме и не должен перетягивать на себя внимание: сумма — главное, что вводят, а валюта чаще всего уже верная. Под это в компоненте выбора валюты есть вариант `compact` — узкий триггер со знаком и кодом.

Отдельный случай — «Перевод»: там валюта не выбирается, а следует за выбранным счётом, и список из одного значения. Такой контрол лучше не показывать выпадающим вовсе.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Решение: нативный <select> убран из QuickActionSheet, на его месте — слот #currency. Дизайн-система не знает ни подключённых валют человека, ни их названий на его языке, поэтому контрол приносит экран: «Расход» и «Доход» кладут в слот AppCurrencySelect variant=compact (тот же компонент, что на остальных экранах), «Перевод» — статичную подпись с кодом счёта, потому что выбор там состоит из одного значения (AC #4). Пропсы currencies/currencyLabel и эмит update:code удалены; code остался — его читает QuickAmountGrid.

Побочная находка при визуальной проверке: компактный список открывался с align=start, и браузер прижимал его вплотную к краю экрана без единого отступа. Исправлено на align=end + max-w-[calc(100vw-2rem)] — список теперь висит на правом крае триггера и не шире экрана. Это же чинит компактный выбор валюты в InflowSheet.

Проверка: реальные 320 и 393 CSS-пикселя (iframe, а не resize окна — окно браузера не опускается ниже 500). На 320: scrollWidth 320 (горизонтального скролла нет), триггер 86×44 px, правый край 304 (отступ 16), поле суммы 194 px, список 274 px внутри вьюпорта. На 393 — то же без сжатия. Снят скриншот обоих состояний, светлая и тёмная тема.

Тесты: quick-action (слот вместо select, select в панели отсутствует), currency-select (align=end + max-w; открытие/Escape/возврат фокуса на триггер), ExpenseFormPage и IncomeSourceFormPage (значение читается из currency-value, валюта выбирается через pickCurrency по названию), TransferSheet (подпись вместо списка из одного значения).

Вне объёма: нативный <select> в AccountsPage — это фильтр по валюте со значением «все», а не выбор валюты суммы; у него есть собственный комментарий с обоснованием. Не трогал.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Быстрые окна «Расход», «Доход» и «Перевод» больше не выбирают валюту нативным списком кодов. QuickActionSheet отдаёт место рядом с суммой в слот #currency: «Расход» и «Доход» ставят туда общий AppCurrencySelect в компактном варианте (поиск по названию ru/en, коду и символу, флаг или знак в строке), «Перевод» — подпись с валютой счёта, потому что выбирать там не из чего. Заодно компактный список перевешен на правый край триггера (align=end) и ограничен шириной экрана: раньше браузер прижимал его вплотную к краю.

Проверено: 6 обновлённых и новых тестов (quick-action, currency-select, ExpenseFormPage, IncomeSourceFormPage, TransferSheet) — выбор валюты в каждом из окон, случай единственного значения, клавиатура и возврат фокуса; визуально и по геометрии на реальных 320 и 393 CSS-пикселях в светлой и тёмной теме: горизонтального скролла нет, триггер 86×44 px с отступом 16 px, поле суммы остаётся главным. bun run lint / typecheck / test (1115 тестов) / build — зелёные.
