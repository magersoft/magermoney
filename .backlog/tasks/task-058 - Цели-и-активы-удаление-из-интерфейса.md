## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
У целей и активов нет способа удалить их из приложения. На экране цели есть только «В архив» (он прячет цель из списка и отвязывает счета), у актива нет даже этого — удалить можно лишь отдельную оценку из журнала. При этом API умеет всё: DELETE /goals/{id} и DELETE /assets/{id} существуют, а во вебе уже написаны неиспользуемые useDeleteGoal и useDeleteAsset. То есть ошибочно созданная цель или актив остаются в базе навсегда.

Архив и удаление — разные вещи, и это надо развести в интерфейсе: архив для достигнутой или отложенной цели, удаление для того, чего вообще не должно было быть. Удаление актива уносит с собой всю историю оценок (в миграции стоит cascade), удаление цели отвязывает счета (on delete set null) — об этом надо предупредить до, а не после.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 На экране цели есть удаление, отделённое от «В архив», и оно вызывает DELETE /goals/{id}
- [ ] #2 На экране актива есть и архив, и удаление; удаление вызывает DELETE /assets/{id}
- [ ] #3 Перед удалением спрашивают подтверждение и называют последствия: у цели — сколько счетов отвяжется, у актива — сколько оценок исчезнет
- [ ] #4 После удаления человек возвращается на экран «Накопления», список обновляется, а отказ сервера показывается тостом
- [ ] #5 У архива актива есть тот же смысл, что у архива цели: он уходит из списка и из суммы капитала
- [ ] #6 Тесты покрывают удаление цели и актива, подтверждение и отказ сервера
- [ ] #7 У целей и активов есть просмотр архива и возврат из него, по образцу счетов: переключатель «Архив (n)» в списке и «Вернуть из архива» на экране записи
- [ ] #8 Архив и удаление заметны там, где живут: сейчас «Убрать цель в архив» — серый ghost-текст в самом низу экрана цели, а сама карточка цели не показывает, что она ведёт на отдельный экран
<!-- AC:END -->
