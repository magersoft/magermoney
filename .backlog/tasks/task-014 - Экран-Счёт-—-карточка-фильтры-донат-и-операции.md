## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Wallet detail у Moni (слайды 12, 15) — самый насыщенный экран референса: карточка сверху, блок Overview со строкой чипов активных фильтров, две плитки доходов и расходов, донат по категориям с легендой, ниже список операций, сгруппированный по периоду.

Для нас это экран счёта. Операции на нём — записи баланса и переводы, у счёта одна валюта, поэтому сноска о курсе здесь не нужна, зато нужен выбор периода: тот же календарь-пикер отдельным шитом с кнопкой применения, что и у референса.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Чистое ядро: apps/web/src/modules/accounts/domain/movements.ts — из журнала записей и выбранного месяца собрать движения (дельта к предыдущей записи), сгруппировать по дням с подытогом, посчитать пришло/ушло, оборот и разбивку по origin. Decimal, без Vue. Тесты первыми.
2. shared/dates: formatMonth(year, month, locale) для подписи периода.
3. PeriodSheet.vue: шит с сеткой 12 месяцев, шагом по году и кнопкой «Применить» (явное применение, AC#3).
4. AccountDetailPage переписать по слайду 12: AccountCard сверху, строка чипов активных фильтров (период + выбранный слайс, снимаются), две плитки StatTile «Пришло»/«Ушло» с дельтой к прошлому месяцу, DonutChart breakdown по origin (оборот в разрыве, легенда фильтрует список), ниже RowGroup по дням с подытогом и TransactionRow на движение. Правка последней ручной записи сохраняется на её строке.
5. Два разных пустых состояния: нет движений за месяц (со сбросом периода) и у счёта вообще нет истории (CTA «записать баланс»).
6. Копия в en.json/ru.json через humanize-text; проверка обеих тем, мобильной ширины и целей нажатия 44px (/impeccable).
7. Тесты экрана обновить; bun run test, lint, typecheck.
